# Making Your First Pull Request

A "pull request" (PR) is how you suggest changes to a project. This is the
classic way to contribute code, documentation, or fixes. This guide walks you
through it using GitHub's website — no command line required.

## The big picture

1. Fork the project (make your own copy).
2. Make your change in your copy.
3. Propose your change to the original project (a pull request).
4. A maintainer reviews and, if all goes well, merges it.

## Step 1: Fork the project

1. Go to the project's GitHub page.
2. Click the **Fork** button in the top right.
3. Choose your account as the destination.
4. GitHub copies the project to your account. This is your "fork".

## Step 2: Find something to fix

Good first contributions:

- Fix a typo in the README.
- Add a missing step to installation instructions.
- Translate a document into another language.
- Add a test or example.

Look for issues labeled `good first issue` or `beginner-friendly`.

## Step 3: Edit a file on GitHub

1. In your fork, find the file you want to change.
2. Click the pencil icon (Edit this file).
3. Make your change.
4. Below the editor, choose **Create a new branch** and give it a name, like
   `fix-readme-typo`.
5. Click **Commit changes**.

## Step 4: Open a pull request

1. GitHub will show a banner asking if you want to compare and create a pull
   request. Click **Compare & pull request**.
2. If you do not see the banner, go to your fork, click **Contribute**, then
   **Open pull request**.
3. Give the PR a clear title, like "Fix typo in installation instructions".
4. Describe what you changed and why.
5. Click **Create pull request**.

## Step 5: Wait for review

- A maintainer may comment or request changes. Reply politely and make any
  requested edits.
- If they merge your PR, congratulations — you are an open-source contributor!
- If they do not merge it, do not take it personally. Maintainers have limited
  time.
