# Reporting Issues

An "issue" is a report of a problem, a question, or a feature request. Reporting
issues is one of the most helpful things a beginner can do for an open-source
project. You do not need to write code.

## When to report an issue

- You found a bug (the software crashes, shows wrong results, or breaks).
- You cannot install or run the software after following the README.
- You have a suggestion for a new feature.
- The documentation is confusing or missing something.

## Before you open an issue

1. Search the project's **Issues** tab to see if someone already reported it.
2. If you find a matching issue, add a comment saying you have the same problem
   instead of opening a new one.
3. Gather details: what you were doing, what happened, what you expected, and
   your operating system (Windows, Mac, Linux).

## How to open an issue on GitHub

1. Go to the project's GitHub page.
2. Click the **Issues** tab at the top.
3. Click **New issue**.
4. Give it a clear title, like "App crashes when I click Save on Windows".
5. In the description, include:
   - What you did
   - What happened
   - What you expected to happen
   - Your operating system and version
   - Any error messages (copy and paste them)
6. Click **Submit new issue**.

## After you submit

- A maintainer might ask follow-up questions. Answer them if you can.
- Be patient. Open-source maintainers are often volunteers.
- Be kind and respectful.
